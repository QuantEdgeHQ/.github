# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability within any repository in this organization, please report it responsibly.

**Do not** open a public issue for security vulnerabilities.

Instead, please report it by:

- Emailing **[security@yourdomain.com]** with a description of the vulnerability, steps to reproduce, and any relevant details (affected repository, version, potential impact)
- If email is unavailable, opening a **private security advisory** via GitHub's "Report a vulnerability" feature on the relevant repository (if enabled)

We ask that you:

- Give us a reasonable amount of time to investigate and address the issue before any public disclosure
- Avoid accessing, modifying, or destroying data that does not belong to you
- Avoid actions that could degrade the availability of our systems (e.g. denial-of-service testing) without prior authorization

## What to Expect

- **Acknowledgment:** We aim to acknowledge reports within 3 business days
- **Assessment:** We will investigate and assess severity, and may follow up with questions
- **Resolution:** Timelines vary based on complexity and severity, but critical issues are prioritized
- **Disclosure:** We will coordinate with you on responsible disclosure timing once a fix is available

## Supported Repositories

This policy applies to all repositories within this organization. Given that trading infrastructure repositories are private, most vulnerability reports will concern public-facing assets (this profile repository, documentation sites, or any public tooling we maintain).

## Scope

The following are considered in scope:

- Authentication or authorization bypass
- Remote code execution
- Injection vulnerabilities (SQL, command, etc.)
- Exposure of sensitive data or credentials
- Vulnerabilities in dependencies we directly maintain or bundle

The following are generally out of scope:

- Vulnerabilities in third-party services we merely integrate with (report to the third party directly)
- Issues requiring physical access to a user's device
- Social engineering attacks
- Reports generated purely by automated scanners without a demonstrated, practical impact

## Recognition

We appreciate the efforts of security researchers who report vulnerabilities responsibly. With your permission, we're happy to credit you once an issue is resolved.
