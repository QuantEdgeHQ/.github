# Contributing

Thank you for your interest in contributing. This document outlines how to contribute to repositories within this organization.

> **Note:** Most repositories in this organization are private and proprietary. Unless a repository explicitly states it is open to external contributions, assume it is not. This guide applies to any repository that welcomes contributions.

## Before You Start

- Check open issues and pull requests to avoid duplicating work
- For significant changes, open an issue first to discuss the approach before writing code
- Make sure you've read the repository's `README.md` for setup instructions and project context

## How to Contribute

1. **Fork** the repository (if external) or create a **branch** (if you have direct access)
2. Use a clear, descriptive branch name, e.g. `fix/order-execution-timeout` or `feat/add-var-calculation`
3. Make your changes, following the code style and conventions already used in the repository
4. Write or update tests where applicable — changes without adequate test coverage may be asked to add them before merging
5. Commit with clear, descriptive messages (see below)
6. Open a pull request against the `main` branch, using the pull request template if available

## Commit Messages

Use clear, present-tense commit messages that describe what the change does:

```
Add volatility-adjusted position sizing to risk module
Fix timestamp mismatch in market data validator
Update README with setup instructions
```

Avoid vague messages like `fix stuff` or `update`.

## Pull Request Guidelines

- Keep pull requests focused on a single change or feature — smaller PRs are easier to review
- Describe **what** changed and **why**, not just a restatement of the diff
- Link related issues where applicable
- Ensure all tests pass and the code builds cleanly before requesting review
- Be responsive to review feedback; if a request is unclear, ask for clarification rather than guessing

## Code Style

- Follow the existing formatting, linting, and naming conventions used in the repository
- Run any provided linters/formatters before committing
- Keep functions and modules focused; avoid unnecessary complexity

## Reporting Bugs

When filing a bug report, please include:

- A clear description of the issue
- Steps to reproduce
- Expected vs. actual behavior
- Environment details (OS, version, etc.) where relevant

## Licensing of Contributions

By submitting a contribution, you agree that your contribution may be used, modified, and distributed as part of the project, under the terms described in the repository's `LICENSE` file or, in its absence, under the organization's `COPYRIGHT.md`.

## Questions

If you're unsure where to start or have questions about contributing, open an issue or check `SUPPORT.md` for other ways to reach us.
